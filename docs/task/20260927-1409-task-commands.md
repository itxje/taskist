## Description

Add `add`, `ls`, `show`, `edit`, `next` and `find` as specified in section 3.8 of plan
`docs/plan/20260927-1154-taskist-mvp.md`, with human output and the JSON `data` shapes of
section 3.9, `--all-projects` on `ls`, `next` and `find`, and colour of the status word and
headings through `anstream` in human output only. Wire `--by` and the actor resolution to the
stored `created_by`, and read the current directory only when a command needs directory scope.

Acceptance:

- Every command succeeds in human and JSON form; JSON `data` has exactly the fields of
  section 3.9 (task fields `id, project, feature, title, body, status, priority, tags,
  created_at, updated_at, closed_at, created_by`; `show` `{task, notes}`; `ls`, `find`
  `{scope, tasks}`; `next` `{scope, task}`), compared as key sets.
- `add` creates a missing feature on first use and reuses it; `--body -` stores stdin; an
  archived project exits 4 `conflict`; no resolvable project exits 2 naming `-p/--project`.
- Actor precedence through the binary: `--by`, then `TASKIST_ACTOR`, then `USER`, then
  `unknown`, read from `created_by` with `tk show --json`.
- With the working directory removed: `--help` and `--version` exit 0, `ls -p <project>
  --json` exits 0 with `scope.source` `flag`, `ls --json` exits 1 with `internal`.
- The forced `project rm` test seeds a tag and a note before removal.
- `ls` default output matches the grouped layout; filters `-f`, `--status` (several values),
  `--tag`, `--all`, `--limit`, `--all-projects`.
- `edit`: each option alone, tag add and remove including values starting with `-`,
  `--no-feature`, move with feature carry-over, no option (exit 2), unknown id (exit 3).
- `next` order and the null result; `find` over title, body and notes, case-insensitive, with
  `%`, `_` and `\` literal, closed tasks only with `--all`.
- Colour: none when piped, present with `CLICOLOR_FORCE=1`, none with `NO_COLOR=1` as well,
  never in JSON.
- No command waits for input: the shared helper closes stdin unless a test supplies a body.

## Notes

### Investigation

- The store had task insertion, listing by project, tags and notes, but no task update and
  no lookup of a project or feature by id; both are needed to render a single task and to
  edit or move one.
- `main` read the current directory before parsing and failed every command, `--help`
  included, when it could not be read. The directory is needed only for directory scope, a
  relative `TASKIST_DB` and a relative `project --path`.
- `--by` was parsed but never read, and no command stored an actor.
- `tk ls` sorted all tasks by priority across projects; the plan asks for a display grouped by
  project and feature with `--limit` applied in display order.
- `anstream`'s automatic mode strips every escape sequence when colour is off, which would
  also strip escape sequences stored in titles, bodies and notes; the plan requires stored
  text to be printed as stored.

### Design

- `Env` holds the current directory either as a given path (tests) or as a reader function
  (`Env::with_current_dir_reader`, used by `main` with `std::env::current_dir`), called only
  when `Env::current_dir` is asked for; a failure is the `internal` error
  `cannot read the current directory: ...`. `Env::absolute` resolves the database path and
  `project --path` without the current directory when they are absolute.
- Colour: `Env::colour` is false when `NO_COLOR` is non-empty, true when `CLICOLOR_FORCE` is
  non-empty, otherwise whether stdout is a terminal (the `anstyle-query` rules, read from the
  captured environment). `output::Paint` adds `anstyle` styles to the status word and to
  headings (project names, feature groups, the `show` title line, `notes:`) only when colour
  is on, padding outside the style. All stdout is written through
  `anstream::AutoStream` with `ColorChoice::Always`, which passes text through unchanged, so
  stored escape sequences are printed as stored and only the added styles depend on the
  colour decision. JSON output never carries styles.
- Command module `command::task`: `add`, `list`, `show`, `edit`, `next`, `find`, each one
  transaction. `add` and `edit` validate every value (title, priority, feature name, tags)
  and read `--body -` from stdin before opening the store. An archived project refuses `add`
  and a move into it with `conflict`.
- `edit -p P`: the target project is looked up by name (`not_found` when missing). The
  feature is `--no-feature` → none, `-f F` → `F` in the target, otherwise on a move the
  current feature's name in the target, created when missing; without a move the feature is
  unchanged. `--tag +T` or `T` adds, `-T` removes, applied in the given order; removing an
  absent tag changes nothing.
- Listing: the covered projects are the scoped one or every non-archived project. Display
  order is project name, feature name with tasks without a feature last, priority,
  `created_at`, id; JSON `tasks` use the same order, so `--limit` cuts the list the human text
  shows. The project heading shows the project's open-task count (the `project ls` number),
  independent of the filters. A blocked task shows its latest `blocked` note. `-f` naming no
  feature of the covered projects is `not_found`. `--status` takes a comma list or repeats
  and conflicts with `--all`.
- `next` takes `todo` and `doing` tasks and orders them by priority, `doing` first, then
  `created_at`, then id.
- `find` lowercases the query and the title, body and note texts and tests for a substring.
  There is no pattern language, so `%`, `_` and `\` match only themselves; lowercasing covers
  non-ASCII letters, which SQLite's `LIKE` would compare case-sensitively.
- Every option that takes a value accepts values beginning with `-` (`allow_hyphen_values`),
  so `--tag -x`, `--body -text` and `--by -bot` are values, never options.
- `anyhow` is removed: `main` no longer has a fallible step of its own. `anstream` 1.0.0 and
  `anstyle` 1.0.14 (the latest releases on crates.io) are added.
- Human forms: `add` prints `added #ID to PROJECT[/FEATURE]: TITLE`, `edit` prints
  `updated #ID in PROJECT[/FEATURE]: TITLE`, `next` prints the task line with its location
  in parentheses or `no open task`, an empty unscoped listing prints `no tasks`.
