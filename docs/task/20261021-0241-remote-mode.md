# 20261021-0241-remote-mode Remote mode: one database served to tk on other machines

## Description

Work now runs on several machines (BKD servers), each with its own `tk` database, so tasks
recorded on one machine are invisible from the others and owner follow-ups get lost. Add a
remote mode: `tk serve` exposes one machine's database, and `tk` on any other machine forwards
its command there when `TASKIST_SERVER` is set, with byte-identical output and exit codes.

Acceptance:

- `tk serve --listen ADDR` runs every forwarded command against its own database and returns
  stdout, stderr and the exit code; it refuses requests without the shared token.
- With `TASKIST_SERVER` and `TASKIST_TOKEN` set, every command except `guide`, `completions`,
  `--help` and `--version` runs on the server; human and JSON output and exit codes equal a
  local run against the same database, including stdin bodies (`-`) and `import FILE`.
- Without `TASKIST_SERVER`, behaviour is unchanged.
- An unreachable server or a refused token is a documented error with its own code and exit
  code, and nothing is written.
- Tests, `docs/guide.md` and `docs/architecture.md` cover the mode.
