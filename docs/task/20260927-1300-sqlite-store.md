## Description

Add the `store` module (connection setup, embedded migrations tracked by `PRAGMA
user_version`, migration 1 with the schema and indexes of plan section 3.5, transaction
helpers, and the queries for projects, features, tasks, tags and notes) and the `model`
module (domain types, name and value validation, and the single transition table). Wire
`tk project ls` far enough to open the database through the production path and print an
empty project list, so the first-open race is testable through the binary. Part of plan
`docs/plan/20260927-1154-taskist-mvp.md`.

Acceptance:

- Opening a missing database creates parent directories (mode 0700 on Unix) and the schema
  at `user_version` 1, in WAL mode with foreign keys on; reopening changes nothing.
- A database with a higher `user_version` is refused with `unsupported_schema`, unchanged.
- Task ids are never reused, also after the task with the highest id is deleted through
  project removal.
- The transition table yields the documented outcome for all 25 pairs of command and status.
- Duplicate project name, duplicate project path, duplicate feature in one project, priority
  outside 0-3 and an unknown status are refused by the database with the typed error.
- Names match `[a-z0-9][a-z0-9-]*` up to 64 characters; titles are trimmed, non-empty and
  single-line (no line feed, vertical tab, form feed, carriage return, next line, line
  separator or paragraph separator inside).
- The `rusqlite` entry enables `bundled` and is preceded by its `# JUSTIFICATION:` line.
- `tk` started through the integration-test helper creates exactly one database, at the
  location resolved from the helper's variables, and runs in the helper's working directory.
- A failure in the middle of a write leaves no partial change.
- Text with SQL syntax is stored and read back verbatim.
- 8 `tk project ls` processes opening one missing database at once all succeed and the
  schema is created once.

## Notes

### Investigation

- The foundation provides `Env::database_path`, the `Error` enum with `unsupported_schema`,
  the output envelopes and an empty `Command` enum; no module touches a database yet.
- crates.io lists `rusqlite` 0.40.2 as the latest stable release (with `libsqlite3-sys`
  0.38.2); it enters `Cargo.toml` with this change, as the foundation record planned.
- The bundled SQLite build turns foreign keys on by default, so the store still sets
  `foreign_keys = ON` explicitly and the pragma test calibrates its reader by switching the
  setting off and on.

### Design

- `Store::open`: create missing parent directories (`DirBuilder`, recursive, mode 0700 on
  Unix); open; `busy_timeout` 5 s; read `user_version` and refuse a newer schema before
  anything is written; `journal_mode = WAL`; `foreign_keys = ON`; `synchronous = NORMAL`;
  then, when the version is below the supported one, apply the pending migrations inside one
  `BEGIN IMMEDIATE` transaction that reads `user_version` again after taking the lock.
  Reading the version before the WAL switch keeps a newer database byte-for-byte unchanged,
  since the switch rewrites the file header.
- The WAL switch on a database still in rollback mode upgrades the read lock of the
  statement to a write lock. When another connection holds a pending write at that moment,
  SQLite returns `SQLITE_BUSY` at once instead of calling the busy handler, because waiting
  could deadlock; the concurrent-open test hit exactly this with 8 processes. SQLite's
  resolution is to run the statement again once its locks are released, so `enable_wal`
  repeats the switch with pauses growing from 1 ms to 50 ms until it succeeds or the 5 s busy
  timeout has passed. Every other statement relies on the busy handler.
- `Store::write` runs a closure in `BEGIN IMMEDIATE`, `Store::read` in a deferred `BEGIN`;
  the transaction commits only when the closure succeeds and rolls back otherwise. Queries
  are methods on `Tx`; SQL text is literal (column lists are joined with `concat!`) and every
  value is a bound parameter. Timestamps come from `strftime('%Y-%m-%dT%H:%M:%fZ','now')`.
- Migrations are embedded SQL files under `src/store/migrations/`; migration `n` brings the
  schema to version `n`. Migration 1 has the five tables, `AUTOINCREMENT` on `task.id`, the
  `CHECK`s on status, priority, note kind and `archived`, and the three indexes.
- Database errors map to typed errors: a unique or primary-key violation is `conflict`, a
  check violation `usage`, a foreign-key violation `not_found`, anything else `internal`.
- `model` holds `Status`, `NoteKind`, `Action`, `Outcome`, the domain structs and the
  validation functions. The transition table is one exhaustive `match` from action to its
  target status and the statuses that change to it; the target itself is a no-op and every
  other status an invalid transition.
- `tk project ls` opens the database at the resolved location (a relative `TASKIST_DB` is
  taken from the captured current directory) and lists projects that are not archived: one
  name per line or `no projects`, and `{"ok":true,"data":[...]}` in JSON.
- Helper checks for `tk` itself: `tk project ls` through `Sandbox::tk` creates exactly the
  file `TASKIST_DB` names, and through `Sandbox::tk_without_db` exactly
  `$XDG_DATA_HOME/taskist/taskist.db`, or `$HOME/.local/share/taskist/taskist.db` when
  `XDG_DATA_HOME` is removed, with no other database file under the temporary directory. To
  show that `tk` runs in the helper's working directory, a holder process keeps the `work`
  directory as its own working directory, the directory is removed and replaced by a link to
  `/proc/<holder>/cwd`; the helper still enters the removed directory, and `tk` then fails
  with the internal current-directory error.
- The helper checks must hold whatever the environment of the test run: the sandbox test
  binary runs the three database-location tests again in a child whose environment sets
  `TASKIST_DB`, `TASKIST_FORMAT` (`json`), `HOME` and `XDG_DATA_HOME` to decoys in a second
  temporary directory. Those tests also expect text output. The parent requires all three to
  pass in the child and the decoy directory to stay empty; a control first shows that an
  unconfined `tk` given the decoys writes the decoy database and prints JSON.
- A title is refused when any of the seven line terminators occurs inside it; all seven are
  white space, so trimming already removes them at both ends.
- Under umask 077 a directory gets mode 0700 without an explicit mode, so the directory test
  also runs `created_directories_are_private` in a child of the unit-test binary started
  through `sh` with umask 022. There a directory created without a mode gets 0755, and the
  child prints such a control directory's mode, which the parent checks.
